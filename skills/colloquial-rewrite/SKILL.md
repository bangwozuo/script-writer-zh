# 口语化改写

把书面稿改成「说给人听」的口播稿：原意不动、事实不增删，逐段给出改动对照与理由。

不做的事：不重写内容主题、不增删事实数字、不做敏感词替换（违禁词改写后依然违禁，
须过 sensitive-word-precheck）。

## 能力描述

四步改写法，每步有量化验收：

1. **拆长句**：单句压到 8-14 字，拆「的」字链与连词；连续 3 句同长 >18 字判 AI 腔，
   目标句长 CV ≥ 0.5
2. **换书面词**：逐词替换表（进行/予以/之/其/亦/均/因此/首先……），同音歧义词重写
3. **注入口语标志**：第二人称 ≥10 个/千字、语气词 2-4 个/百字、每 3-5 句一个 ≤6 字
   呼吸口、数字口语化（3.2 万元 → 三万二）
4. **清 AI 腔**：衔接词 <1 个/千字、完美三段式改结论前置、抽象词换具体动作+数字

改完按 **4-5 字/秒** 核字数：60s 稿 240-300 字、45s 稿 180-225 字；字数下降
10-20% 正常，>30% 说明删了信息要回核。

**语气画像优先**：有 persona-voice-library 画像时，句长/称呼/口头禅以画像为准，
本技能通用标准作兜底。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `text` | string | ✅ | 待改写的书面稿 |
| `target_duration_s` | number | ⬜ | 目标成片时长（用于核字数），缺省按 60s 校验 |
| `voice_profile` | object | ⬜ | persona-voice-library 的改写约束清单 |

## 输出规格

- `rewritten`：改写后全文（附字数与估算时长）
- `changes`：逐段改动对照（原文/改写/理由）
- `self_check`：六项自查（平均句长/连句/衔接词/语气词/人称/字数变化）

## 使用步骤

### 方式一：直接使用（最快）

1. 打开任意支持自定义提示词的 AI 工具
2. 复制 `prompt.txt` 的**全部内容**作为系统提示词
3. 提供书面稿（可选：目标时长、语气画像）
4. 得到改写稿 + 改动对照 + 自查表

### 方式二：在主流平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **Claude / ChatGPT** | Project/GPT Instructions → 粘贴 `prompt.txt` |

### 校验配套

自查表的统计值可用 `ai-trace-check` 脚本实测（句长 CV、衔接词密度、口语标志词
密度同一口径），避免模型自估误差。

## 边界（不做的事）

- ❌ 不增删事实——改动前后事实清单必须一致，引用与数据出处原样保留
- ❌ 不制造同音歧义（全部/全不、期中/其中这类听觉分不清的表述必须重写）
- ❌ 语气词不超 4 个/百字——油腻比生硬更掉粉
- ❌ 有画像时不守画像约束（句长/称呼/口头禅上限）的改写不放行
- ❌ 改写不豁免敏感词审查，发布前仍须过 sensitive-word-precheck

## 调用示例

**输入**（`examples/input.json`）：一篇 346 字的书面稿（副业选题，书面味浓：
「首先/其次/综上所述」「进行评估」「显著提升」）。

**输出**（按 prompt 走一遍）：改写稿 288 字（降 16.8%，估算口播 64 秒），
平均句长 9.8 字，衔接词 7 处删 6 处、改写 1 处，「首先/其次/最后」三段式改结论前置，
「进行评估」→「算算账」。逐段对照 14 处改动，每处标注对应规则。

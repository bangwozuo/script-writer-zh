# 使用示例 —— 人设语气库

## 示例 1：副业类创作者画像（脚本实跑，examples/input.json）

**输入**：「阿栋聊副业」3 篇口播稿（柠檬茶摆摊 / 闲鱼二手 / 接单平台对比），合计 812 字。

**脚本实跑结果**（退出码 0）：

| 指标 | 值 | 解读 |
|---|---|---|
| 平均句长 | 9.7 字 | 典型短视频口播节奏 |
| 句长 CV | 0.51 | 长短句交错的节奏已成型 |
| 语气词 | 0.7 个/百字 | 偏低——这人靠「咱就是说」不靠「啊呢吧」 |
| 人称 | 39 个/千字 | 对镜头说话感强 |
| 口头禅 | 「就是说」频次 5 跨 3 篇 | 大概率人设梗，待确认 |

**改写约束落地效果**：一篇书面稿「首先应当评估自身的时间分配情况」改写为
「先问问自己，能不能站四个小时」——句长 8 字、有人称、无衔接词，
三条约束同时满足。

## 示例 2：样本不足时的边界行为

**输入**：只有 1 篇 250 字的稿件。

**结果**：脚本 SystemExit 退出（样本不足 3 篇），输出索要清单：
「还差 2 篇 / 约 550 字。建议补充：爆款篇 1 篇（看流量高峰期的表达）+
日常篇 1 篇（看基线风格）+ 翻车篇 1 篇（看数据差时的表达）」。
不凑数、不凭空补人设——这是 prompt 的硬边界。

## 示例 3：代笔稿污染画像的拦截

**输入**：3 篇样本中 1 篇是 MCN 代笔（平均句长 22 字，其余两篇 9-10 字）。

**结果**：逐篇统计显示该篇平均句长偏离整体 100%+，触发 prompt「工作方法 2」
的异常标注，输出待确认清单：「第 3 篇句长特征显著偏离其余样本，疑似代笔或
转型期作品，请确认是否纳入画像。纳入将拉高平均句长目标 3 字。」

## 示例 4：口头禅候选的甄别

**输入**：同示例 1。

**结果**：候选表 10 项中，「就是说」（频次 5 跨 3 篇）与「你别」（劝阻句式）
被模型标注为「建议确认后人设梗」；「个月」「三个」「十块」为量词/价格巧合，
「的评论」是跨词边界的噪音，均不写入约束。**统计只负责入围，人设判断归人**。
